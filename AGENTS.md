# SMS Guard — правила проекта

- Источник требований: `docs/technical_specification.pdf` (47 страниц); матрица — `docs/requirements_matrix.md`. Не выдумывать требования при недоступности источника.
- Разрешённый текущий объём: задания 1–6. Задание 7 и последующие выполнять только после явного подтверждения пользователя. Классификатор сейчас не обучать. Пустые пакеты не означают реализованную функциональность.
- Python 3.13, FastAPI, SQLAlchemy 2, Alembic, SQLite, Jinja2, Bootstrap 5; далее scikit-learn, pandas, NumPy, NLTK, Chart.js. Django и Docker не добавлять.
- Сохранять существующие файлы; не удалять их без согласования. Каждый этап завершать отдельным Git-коммитом с `task-NN: ...`. Не подменять авторство пользователя; не публиковать репозиторий без запроса.
- Настройки из окружения / `.env`, пример без секретов. `.env`, БД, логи, оригинальные/производные UCI-данные и артефакты ML не коммитить. Исключение: искусственный `data/raw/custom_ru.csv`, его авторский исходник и агрегированные отчёты воспроизводимости отслеживаются в Git. DEBUG выключен по умолчанию.
- URL анализировать исключительно как строки: никаких HTTP-запросов, DNS, переходов и редиректов к пользовательским адресам. tldextract использовать с локальным PSL, без автоматической загрузки.
- Только ORM / параметризованный SQL. Jinja2 autoescape; пользовательский текст в JavaScript только через textContent. Не использовать safe/innerHTML для пользовательских данных. Ссылки в результатах неактивны.
- При реализации авторизации: хеширование с солью, CSRF для всех POST-форм, HttpOnly/SameSite=Lax и Secure при HTTPS, изоляция записей владельца, 5 ошибок входа → пауза ≥60 с, лимит анализов 30/мин на пользователя.
- Не записывать SMS, пароли, токены, query strings и пользовательские URL в логи. Хранить полный SMS только по согласию (по умолчанию false), иначе маскировать телефоны, карты и суммы. Не использовать реальные SMS третьих лиц без согласия.
- Категорически запрещено выдумывать ML-метрики, вероятности, датасеты, результаты обучения или тестов. Нет модели — нет предсказания. Макеты маркировать как макеты. Фиксировать фактические ошибки и недостигнутые пороги.
- Удалять дубликаты до разбиения. SMS: 70/15/15, random_state=42; URL: непересекающиеся группы регистрируемого домена. fit только на train, подбор на val/CV train, тест один раз. Сохранять индексы, параметры, версии, лицензии и происхождение данных.
- Изменение пользователя от 06.11.2026: казахский язык полностью исключён (отклонение DEV-01 от исходного PDF); целевые языки en/ru. Основной обучающий корпус только английский UCI; ≥100 искусственных русских SMS — отдельный test-only набор, не обучение, CV, EDA или подбор порогов. Полноценную ML-поддержку ru без обучающих данных и независимых метрик не заявлять; для ru запланированы словарь и URL-анализ. Английский SMS-классификатор для ru не запускать и P_sms для ru не выдавать. Сейчас URL-модуль ещё не реализован. Система не гарантирует безопасность.
- Проверки перед завершением изменений: `python -m pytest`, `python -m ruff check .`, `python -m ruff format --check .`, `python -m pip check`, проверка HTTP-запуска. Для будущих ML/risk — осмысленные граничные тесты и покрытие ≥60%; не выдавать проверку каркаса за проверку ML.
- Документация и пользовательские ошибки на русском. Указывать источник, критерий приёмки, фактическую проверку и ограничения. Не называть непроведённые проверки успешными.
