# Задание 4 — общая нормализация и удаление дубликатов

Контракт `ml.preprocessing.normalize_sms(text) -> str`: NFKC, нижний регистр, управляющие Unicode-символы→пробел, email→`<email>`, URL→`<url>`, суммы→`<money>`, телефоны7–15цифр→`<phone>`, прочие числа→`<num>`, повторные !/?→один соответствующий символ, схлопывание пробелов. Суммы распознаются до телефонов, email до URL; это предотвращает поглощение сущностей. Строка не изменяется на месте, исходный `text_raw` сохраняется, `text_clean` формируется отдельно. Нестроковый аргумент отклоняется, пропуски обрабатываются на уровне таблицы.

Кириллица, ё, эмодзи и Unicode-буквы не удаляются. Казахская функциональность/корпус исключены DEV-01; общее сохранение Unicode не объявляет языковую поддержку. По заданию4 используются lowercase-токены (DEV-02), валюта распознаётся независимо от языка. Денежные символы исходного ТЗ сохранены как контракт нормализации.

Не открываются URL, не разрешаются DNS. Функция общая для подготовки и будущего pipeline; необязательное удаление стоп-слов по умолчанию выключено. NLTK RegexpTokenizer + локальные en/ru списки из официального nltk_data, происхождение/SHA и оригинальный README сохранены в `ml/resources`. Runtime не скачивает корпуса. Эффект стоп-слов на качество относится к заданию8 и сейчас не измерялся.

Команда `python -m ml.preprocessing` читает только UCI `sms_raw.csv`, пишет `data/processed/sms_clean.csv`. Русский test-only не читается. Дубликаты удаляются до любого разбиения, сохраняется первый исходный id; при противоречивых метках по нормализованному тексту удаляется вся конфликтная группа (фактически таких групп0). Контрольные суммы и все удалённые id в `reports/04_preprocessing.json`.
