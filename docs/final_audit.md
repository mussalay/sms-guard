### Дополнительные наблюдения по коду и контрольным примерам

1. `URL.finditer('bank.xyz/login')` и `URL.finditer('bank.kz/login')` не находят ссылку без схемы; `https://bank.xyz/login`, `bit.ly/x`, `пример.рф/вход` находятся. Сам отдельный URL-validator принимает такие домены. Следовательно, поиск ссылок внутри SMS покрывает ограниченный список TLD, а не все домены.
2. `compute_risk(None, .2, [], [{'shortener':1,'at_sign':1}])` вернул общую причину «Выраженных признаков угрозы не обнаружено». Флаги могут быть показаны в дочернем URL-блоке, но общий список причин не выполняет буквально требование «каждый флаг даёт причину».
3. Для `http://goggle.test/login` публичный `extract_url_features` даёт brand_similarity=1, classifier `model_features` —0. Это сознательно замороженная совместимость с оценённым v1, не новый leakage, но показываемая таблица не является точной копией всех входов RF. Scheme/www также нормализуются перед RF: HTTPS-признак в его модельных входах становится постоянным 0. Интерпретировать feature table как точную атрибуцию RF нельзя.
4. `/openapi.json` для POST SMS не содержит requestBody. Swagger перечисляет маршрут, но не предоставляет полноценного описания JSON-ввода. README содержит таблицу полей; наличие Swagger не равно полному контракту.
5. Неожиданные исключения не охвачены общим JSON500-handler; обрабатываются HTTPException и RequestValidationError. Поведение отсутствующей модели подтверждено, произвольно повреждённого joblib — нет. SHA-проверка не делает недоверенный joblib безопасным и не подтверждает его издателя.
6. `.env.example` хранит устаревший комментарий «future authentication», AGENTS.md — «URL-модуль ещё не реализован»; старые этапные отчёты также говорят об отсутствии моделей. Исторические документы полезны как история, но не должны предъявляться как текущее состояние.

Ограничители анализов и ошибок входа находятся в памяти одного процесса: после перезапуска сбрасываются и не разделяются между workers. Для локального single-worker это раскрытое ограничение; многопроцессный deployment потребует общего хранилища, средняя сложность. Готовность к production не подтверждается.

### Некритические: документация и удобство

- Устаревшие предложения AGENTS.md, .env.example и этапных документов; разнобой пробелов и обозначений. Малая сложность. Исторические результаты нельзя переписывать под текущее состояние.
- Английские имена URL-признаков и кодов в части UI, одинаковые Dashboard и statistics, сокращённое описание ER-полей. Малая/средняя сложность. Для записки ER стоит раскрыть подробнее.
- Браузерный smoke жёстко привязан к пути Windows Edge. Переносимый запуск — малая/средняя сложность; текущая машина подтверждена прежним прогоном.
- Низкое покрытие training CLI, seed и команды запуска при достаточном общем проценте. Средняя сложность; нужны осмысленные проверки, а не тесты, повторяющие код.
- SHA подтверждает совпадение с sidecar, но не доверенность издателя joblib. Для защиты достаточно переноса доверенных артефактов; для распространения нужен отдельный механизм доверия.
