# Согласуемые отклонения от исходного ТЗ

## DEV-01 — исключение казахского языка

Основание: явное изменение требований пользователем 06.11.2026 в этом сеансе. Статус: принято в рабочую спецификацию по указанию пользователя; для академической сдачи согласовать с руководителем как отклонение от PDF. Дополнительное разрешение для текущей реализации не требуется.

Исходный PDF и его текстовая копия остаются неизменными историческими источниками. Новая спецификация имеет приоритет: только en/ru; нет kk-корпуса, детектора, словаря, теста качества и демонстрационных сценариев. Требование сохранить Unicode при нормализации остаётся общим, но не означает языковую поддержку.

Изменены ФТ-2.2/2.8, ДАН-06, МЛ-05, задания 3/4/8/12/13/18 и демонстрация. Вместо custom_ru_kk.csv создаётся `data/raw/custom_ru.csv`: ≥100 искусственных русских SMS с разметкой, исключительно test-only. Основной обучающий источник — английский UCI SMS Spam Collection.

Русский язык пока ограничен правилами мошеннических выражений и анализом URL в будущих заданиях 9–13. На этапе 6 словарь минимально используется только для ручного признака «число групп». Это не готовый сервис анализа. Нельзя выдавать английскую модель за доказанную русскоязычную: нужны соответствующие обучающие данные и независимые метрики. До этого английский SMS-классификатор не применяется к ru, P_sms для ru отсутствует; будущий риск должен корректно учитывать отсутствие этой вероятности. Собственный русский тест нельзя использовать для обучения, EDA, настройки словаря, выбора модели или калибровки; для калибровки позднее потребуется отдельный набор.

## DEV-02 — регистр токенов

PDF стр.5 задаёт верхний регистр, задание4 стр.22 — нижний. Единый контракт `normalize_sms`: `<url>`, `<email>`, `<phone>`, `<money>`, `<num>`. Все будущие pipeline используют его без второго несовместимого преобразования. Символы валют из исходного задания4 распознаются как сущности независимо от языка; это не языковая поддержка.
