## Адаптация архитектуры

Модульный монолит: `app/main.py` → API / Jinja2 → сервисы `app/analysis` → отдельные `ml/` и `risk/` → SQLAlchemy → SQLite. `app/accounts` и `app/dashboard` пока только пакеты. `app/core` — env и логирование; `app/db` — DeclarativeBase, engine, session factory. Alembic читает ту же конфигурацию; предметные миграции относятся к заданию 16. Вместо manage.py runserver/check — `python -m uvicorn app.main:app` и pytest/lint/import/HTTP-проверки; вместо transaction.atomic — SQLAlchemy session.begin; вместо Django aggregations — SQLAlchemy SQL functions/group_by. Jupyter и дополнительные инструменты загрузки датасетов добавляются на соответствующих этапах, Chart.js — на этапе 17.

SQLite выбран пользователем для локальной разработки: не требует сервера, подходит одному экземпляру и учебной демонстрации. Ограничения — конкурирующие записи и отсутствие многосерверного развёртывания. Демонстрация только на SQLite допустима ТЗ при этом обосновании; соответствие нагрузочным целям ещё предстоит измерить.

## Неоднозначности, которые нужно учесть до соответствующего этапа

1. Стр. 5: токены в верхнем регистре; стр. 22: в нижнем. Планируем единый lowercase-контракт задания 4 с документированным соответствием.
2. Стр. 13: собственный ru только для теста (DEV-01); стр. 32: он же для калибровки риска. Нельзя подбирать и отчитываться на одних данных: до задания 13 выделить отдельный calibration-набор, сохранив нетронутый языковой тест. Это проектное решение, не новое требование PDF.
3. Стр. 26: оценить на test, затем refit train+val. Test-метрики относятся к оценённому артефакту до refit; хранить идентификаторы обоих, не приписывать refit-модели непроведённый тест.
4. Стр. 44: четыре карточки, стр. 35: шесть показателей. Предлагается показать все шесть показателей; окончательная компоновка на задании 17.
5. Стр. 13 требует стратификации, стр. 29 — domain grouping: для URL приоритет непересечению доменов; фактический баланс и отклонение долей описать.
6. Health: стр. 21 задаёт минимальное `status=ok`, стр. 18 требует статус моделей. Ответ расширен полем `models` без ложной готовности анализа.
7. Агрегированный админский доступ не даёт прав на тексты чужих SMS. При реализации Dashboard требуется отдельная проверка приватности.
