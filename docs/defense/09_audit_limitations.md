Основание: `docs/final_audit.md`. Это честные объяснения, а не оправдание неполноты. Исправлений при подготовке нет. Полные:1,3,4,5,6,9,10,12. Частичные:2,7,8,11,13,14,15,16,17,18. DEV-01 для академической сдачи нужно согласовать с руководителем.

## Задание 2. Среда и перенос

**Реализовано.** Каркас, env, logging, Bootstrap и health работают.
**Не выполнено.** Не подтверждено чистое клонирование с полноценной аналитикой: модели вне Git.
**Почему важно.** Воспроизводимость на компьютере преподавателя отличается от запуска у автора.
**Как объяснить.** «Я проверил существующее окружение; переносу нужны доверенные joblib и metadata.»
**Критический вопрос.** Разве инструкции README недостаточно?
**Правильный ответ.** Они устанавливают библиотеки, но сами не создают обученные артефакты.
**Что нужно для исправления.** Подготовить комплект и проверить отдельное чистое окружение без нового обучения.

## Задание 7. Baseline

**Реализовано.** NB alpha1 обучен, validation-метрики, сохранение и reload есть.
**Не выполнено.** 5FN+5FP показаны для итоговой SVM, а не baseline; predict_sms использует финальную модель.
**Почему важно.** Baseline нужен для анализа исходных ошибок до выбора лучшего алгоритма.
**Как объяснить.** «Не буду выдавать анализ SVM за анализ baseline.»
**Критический вопрос.** Разве в notebook нет десяти ошибок?
**Правильный ответ.** Есть, но они относятся к другому артефакту и test.
**Что нужно для исправления.** Отдельно разобрать baseline validation и пояснить действующий predictor.

## Задание 8. Сравнение SMS

**Реализовано.** Три алгоритма, девять конфигураций, validation F2, порог и один test.
**Не выполнено.** Нет полного 5-fold подбора, ablation, train+val refit и полной сравнительной latency.
**Почему важно.** Калибровочный CV не заменяет CV гиперпараметров.
**Как объяснить.** «Использована малая train/validation-сетка; сохранена именно оценённая модель. Это частичная приёмка.»
**Критический вопрос.** Почему не переобучить сейчас?
**Правильный ответ.** Новые веса не получают автоматически метрики старого артефакта; старый test нельзя использовать для адаптивного выбора.
**Что нужно для исправления.** Отдельный версионированный эксперимент с новым holdout или согласование обоснованного отклонения.

## Задание 11. URL-модель

**Реализовано.** LR/RF, пороги validation, один test, RF importance и 20 искусственных URL.
**Не выполнено.** Нет CV-подбора, опубликованных LR coefficients; цели качества не достигнуты.
**Почему важно.** Реальная модель может быть недостаточно хороша для надёжного применения.
**Как объяснить.** «Покажу 921 FP и 571 FN, а не ожидаемые целевые показатели.»
**Критический вопрос.** Зачем показывать такую модель?
**Правильный ответ.** Как исследовательский результат с диагностикой ограничений, а не сертифицированную защиту.
**Что нужно для исправления.** Исследовать bias, провести domain-aware CV и независимую проверку, не тюнинг текущего test.

## Задание 13. Risk Scoring

**Реализовано.** Формула, overrides, YAML, EN calibration и граничные тесты.
**Не выполнено.** Нет независимой русской калибровки; общий список пропускает некоторые URL-флаги; часть правил в Python.
**Почему важно.** Причины должны соответствовать всем сигналам, веса — проверенным данным.
**Как объяснить.** «Score — эвристика, не вероятность fraud; общие причины пока не полностью охватывают URL-блок.»
**Критический вопрос.** Почему 22 вместо 35?
**Правильный ответ.** Граница подобрана на английской validation для Recall среднего+≥.95; это не доказательство русского качества.
**Что нужно для исправления.** Отдельный ru calibration, полные причины, ясный конфигурационный контракт.

## Задание 14. API

**Реализовано.** Все основные маршруты, auth, CSRF, owner404, лимиты,503 и ORM работают.
**Не выполнено.** В OpenAPI нет полного requestBody анализа, нет общего JSON-handler неожиданных 500.
**Почему важно.** Перечень маршрутов не является полным контрактом ввода и ошибок.
**Как объяснить.** «JSON проверяется вручную, поэтому Swagger не описывает его полностью.»
**Критический вопрос.** Но /docs открывается?
**Правильный ответ.** Да, доступность UI документации и полнота схем — разные проверки.
**Что нужно для исправления.** Типизированные тела/ответы, безопасный handler и контрактные тесты при отдельной разработке.

## Задание 15. Интерфейс

**Реализовано.** Формы, fetch, loading, примеры, результаты и три ширины экрана.
**Не выполнено.** Контраст 4.5:1 не измерен; ошибки выводятся сверху, а не возле поля.
**Почему важно.** Адаптивность не равна доступности.
**Как объяснить.** «Основные страницы работают, но полная UI-приёмка не закрыта.»
**Критический вопрос.** Разве цвет достаточен?
**Правильный ответ.** Нет, поэтому есть текст и символы badge; контраст всё равно требуется измерить.
**Что нужно для исправления.** Проверить контраст, inline-ошибки, клавиатуру и все состояния.

## Задание 16. База и история

**Реализовано.** Семь таблиц, миграция с нуля, транзакции, mask, owner-фильтры, профиль и seed.
**Не выполнено.** Нет отдельной колонки уровня риска в таблице истории; ER сокращён.
**Почему важно.** Состав строки истории — тоже обязательный критерий 16.5.
**Как объяснить.** «Поле рассчитано и хранится в БД/API, пробел относится к отображению.»
**Критический вопрос.** Значит уровень не вычисляется?
**Правильный ответ.** Вычисляется; отсутствие колонки не означает отсутствие алгоритма или защиты истории.
**Что нужно для исправления.** Отобразить поле при отдельном исправлении, уточнить ER и оформить кейсы.

## Задание 17. Dashboard

**Реализовано.** SQL-агрегаты, карточки, графики, периоды, admin, empty state и последние 10.

**Как объяснить.** «Измерено около.021 с для API; browser≤2 с не утверждаю.»
**Критический вопрос.** Почему Chart.js не подтверждает скорость?
**Правильный ответ.** Ещё нужны загрузка ресурсов, JavaScript, layout и render.
**Что нужно для исправления.** Отдельный браузерный замер с фиксацией данных/железа, подписи осей.

## Как не защищаться

Не говорить «модель может ошибаться, поэтому качество неважно». Ошибка допустима для вероятностной системы, но её частота ограничивает применение. Быстрый режим объясняет объём работ, а не доказывает соответствие PDF. Не обещать обнаружение всех видов мошенничества по английскому spam-корпусу.
