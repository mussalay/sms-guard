## URL

PhiUSIIL UCI967, CC BY4.0, Prasad/Chandra:235795 исходных URL. Читаются только URL, label, без готовых HTML/сетевых признаков. Метка 1legitimate/0phishing инвертируется. Удалено 8 невалидных,84 строки конфликтных групп,2201 дубликат;233502 после очистки, затем стратифицированная подвыборка 50000:28867 legitimate/21133 phishing.

|Часть|Строк|legitimate|phishing|
|---|---:|---:|---:|
|train|33360|20210|13150|
|validation|10121|4364|5757|

GroupShuffleSplit по регистрируемому домену не допускает общих доменов между частями. Размеры строк 66.72/20.24/13.04% отличаются от 70/15/15, поскольку делятся группы. Доля phishing validation≈56.88%, test≈34.15%: состав частей существенно различается.

22 числовых признака из строки: длины, счётчики, IP/порт/схема, слова, сокращатель, маскировка, энтропия, TLD и параметры. model_url унифицирует scheme=http и удаляет www, уменьшая форматную подсказку источника. HTTPS-координата RF становится постоянной 0; это компромисс, а не доказательство, что HTTPS не имеет смысла вообще. Public extractor дополнительно улучшен для reserved/IDNA, а RF использует замороженный v1: показанные признаки не всегда точная копия модельных.

Пороги **t1=.14407261716662403**, **t2=.28814523433324807**. t2 выбран по validation; t1=min(t2/2,5-й percentile вероятностей positive на validation). ## Почему URL хуже: факт, гипотеза, рекомендация

**Факт:**22 признака, новые домены, сдвиг долей классов, падение validationF2.894298 до test.720819, ложная тревога на example.com/about. **Гипотезы:** source/path bias, разная сложность групп, недостаток строковых сигналов, особенности калибровки. Это не доказанное причинное объяснение. Нельзя объявить число признаков единственной причиной: SMS и URL имеют разные задачи, корпуса и split.

Теория зависимости Precision от prior: P=TPR·π/(TPR·π+FPR·(1−π)), π — доля positive. При TPR.9, FPR.1,π.5 получаем P.9; приπ.1 —P.5. Это учебный пример, не восстановление причин нашей матрицы. Падение ROC нельзя объяснить только prior: важны условные распределения примеров.

Будущее корректное улучшение: сформулировать гипотезы, проверять train/validation, сделать domain-aware CV, собрать независимый finalholdout, версионировать признаки/калибровку. Нельзя подбирать по уже использованному test, удалять неудобные строки или добавлять whitelist тестовых доменов. Нельзя открывать подозрительные сайты ради получения признаков.

## Что показывать в артефактах

SMS baseline — NBalpha1, threshold.5; SMS model — calibratedSVM с вложенным preprocessing/FeatureUnion/scaler; URL model — RF, а строковый preprocessing в Python-коде. Metadata содержит версию 1.0.0, дату, источники, параметры, пороги, метрики и SHA. URL joblib без соответствующего кода не является полным inference-пакетом.

ModelStore проверяет hash и загружает доверенные файлы; hash не подтверждает издателя. Недоверенный joblib может исполнять код при загрузке. Модели и данные вне Git требуют отдельного доверенного переноса.

Исторический model_restart.json: SMS singlemedian≈10.72ms, p95≈11.88ms; batchtest≈.612ms/SMS — другая методика с амортизацией пакета. Полная одиночная latency всех алгоритмов не опубликована. Эти значения не являются гарантией на другом железе. При подготовке проверены только новые искусственные примеры из 10, без повторного test и без обучения.
