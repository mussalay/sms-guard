# 04. Machine Learning: три уровня понимания

Английский термин сначала переводится; уровень 1 — интуиция, уровень 2 — ответ преподавателю, уровень 3 — формула или ограничение. Формулы — теория; только числа с пометкой «SMS Guard» относятся к измеренным результатам проекта. x — вектор признаков, y — истинная метка 0/1, p — оценка вероятности положительного класса, n — число объектов. ln — натуральный логарифм, exp — экспонента.

## Основы

### 1. Machine Learning — машинное обучение

**Уровень 1.** Алгоритм находит закономерности по примерам вместо ручного перечисления всех SMS.

**Уровень 2.** Обучение выбирает параметры θ функции fθ(x), уменьшая ошибку на train. В SMS Guard это веса линейного классификатора или структура деревьев, а не runtime-словарь.

**Уровень 3.** Общий принцип: θ*=argminθ [1/n·ΣL(yᵢ, fθ(xᵢ))+λΩ(θ)]. L — функция потерь, Ω — штраф сложности, λ — сила штрафа. Теоретический пример: усиление λ уменьшает норму весов, но может повысить bias. Не вся программа «учится»: API и SQL работают по заданным правилам.

### 2. Supervised Learning — обучение с учителем

**Уровень 1.** В примерах уже указано, какой SMS ham, а какой spam.

**Уровень 2.** Учитель — разметка y, а не человек, наблюдающий каждый шаг fit. Модель получает пары(x, y); качество разметки ограничивает качество вывода.

**Уровень 3.** Мы приближаем P(y|x) для наблюдаемого распределения. Смена определения y со spam на fraud нарушает смысл цели: хороший оптимизатор не исправляет семантическое несоответствие меток. В проекте URL-метки инвертируются до обучения.

### 3. Classification — классификация

**Уровень 1.** Нужно выбрать категорию, а не произвольное число вроде температуры.

**Уровень 2.** Классификатор сопоставляет входу один из конечного множества классов. Вероятность и класс — разные выходы: p=.4 может дать метку 1 при пороге .3.

**Уровень 3.** Решение зависит от функции стоимости. При идеально калиброванной p и стоимостях C_FP, C_FN оптимальный порог C_FP/(C_FP+C_FN), если нет других издержек. При C_FN=4, C_FP=1 это.2. В проекте порог выбирался эмпирически по validation F2, не этой формулой.

### 4. Binary Classification — бинарная классификация

**Уровень 1.** Есть два класса:0 и 1.

**Уровень 2.** SMS Guard обучает ham/spam и legitimate/phishing отдельно. Три UI-категории URL получаются двумя порогами бинарной вероятности, не трёхклассовым fit.

**Уровень 3.** При p<t1 имеем SAFE, t1≤p<t2 — SUSPICIOUS, p≥t2 — DANGEROUS. Например p=.2 при .144/.288 даёт среднюю категорию. Общий Risk Score может повышаться overrides независимо от binary label.

### 5. Features и Labels — признаки и метки

**Уровень 1.** Признаки описывают SMS; метка говорит, к какому классу он относится.

**Уровень 2.** x — числовой вектор, y — целевая переменная. SMS имеет 59924 координаты, URL22. id и label не должны случайно стать входными признаками.

**Уровень 3.** Матрица X имеет размер n×d: SMS train3594×59924. Большое d не означает столько же независимых смыслов: n-граммы коррелированы. Лексические признаки могут нести source bias — смещение источника, а не угрозу.

### 6. Training, Validation, Test — обучение, настройка, итоговая проверка

**Уровень 1.** Учебник, пробный экзамен и неприкосновенный финальный экзамен.

**Уровень 2.** Train учит vocabulary/scaler/model; validation выбирает параметры, модель и порог; test оценивает уже зафиксированное решение. В проекте SMS3594/770/771.

**Уровень 3.** Любое решение по результатам test превращает его в дополнительную validation. Размер test771 даёт конечную статистическую неопределённость:88/93 recall — оценка, не точное качество на всех будущих SMS. Интервалы неопределённости в проекте не опубликованы.

### 7. Data Leakage — утечка данных

**Уровень 1.** Модель получает подсказки из экзамена до проверки.

**Уровень 2.** Дубликаты между частями, fit TF-IDF на всём корпусе, подбор порога на test и общие URL-домены могут завысить оценку. Предобработка с обучаемым состоянием fit только на train.

**Уровень 3.** IDF зависит даже от неразмеченных test-текстов: это transductive-информация, поэтому train-only vocabulary/IDF обязательны в данном протоколе. В SVM calibration CV весь pipeline находится внутри fold, иначе калибратор увидит признаки, обученные на своей проверочной части.

### 8. Overfitting и Underfitting — переобучение и недообучение

**Уровень 1.** Переобучение — заучить примеры; недообучение — не понять даже простую закономерность.

**Уровень 2.** Сравнивают train/validation качество, learning curves и стабильность. Переобучение часто даёт большой разрыв, недообучение — низкое качество обеих частей.

**Уровень 3.** Высокая variance — чувствительность к обучающей выборке; bias — систематическое ограничение семейства. RF max_depth ограничивает сложность, C у линейных моделей регулирует штраф. По одному падению URL test нельзя доказать только overfitting: возможен distribution shift.

### 9. Class Imbalance — дисбаланс классов

**Уровень 1.** Безопасных SMS значительно больше, чем spam.

**Уровень 2.** Accuracy может быть высокой у модели «всегда ham». Используют стратификацию, class_weight и метрики положительного класса. В чистом UCI618 spam из 5135.

**Уровень 3.** balanced задаёт w_c=n/(K·n_c), K — число классов, n_c — частота класса. Для SMS train вес spam≈3594/(2·433)=4.15, ham≈.568. Взвешенное обучение не гарантирует калиброванные вероятности на реальном prior.

### 10. Cross-validation — перекрёстная проверка

**Уровень 1.** Несколько раз меняем учебную и проверочную части внутри train.

**Уровень 2.** В 5-fold train делится на пять частей: четыре учат, одна оценивает, роли меняются. StratifiedKFold сохраняет доли классов; для URL нужен учёт групп доменов.

**Уровень 3.** CV-score=(1/K)Σs_k. Это оценка устойчивости, но не новый независимый test. Подбор множества параметров по тем же folds может переобучить выбор; nested CV (вложенная проверка) разделяет selection/evaluation. В проекте 5 fold есть у SVM calibration, не у полного hyperparameter search.

### 11. Hyperparameter Tuning — подбор гиперпараметров

**Уровень 1.** Выбираем настройки алгоритма, например C или глубину дерева.

**Уровень 2.** Параметры модели учатся fit; гиперпараметры задаются до fit. В проекте небольшой явный цикл по 3 значениям alpha/C и 2 глубинам RF, выбор на validation.

**Уровень 3.** GridSearch перебирает декартово произведение настроек, RandomizedSearch случайные комбинации. Число fit для 3 настроек×5 fold=15, без финального refit. Увеличение сетки повышает вычислительную цену и риск переадаптации к validation.

### 12. Pipeline — конвейер обработки

**Уровень 1.** Один объект выполняет все шаги в нужном порядке.

**Уровень 2.** scikit-learn Pipeline вызывает fit_transform промежуточных шагов и fit последнего; predict повторяет transform и inference. FeatureUnion соединяет признаки параллельных ветвей.

**Уровень 3.** Сам Pipeline не спасает leakage, если подать ему test в fit. В проекте для NB/LR первые fitted features берутся из сохранённого train-only объекта, classifier учится на frozen X_train. SVM хранит полный pipeline внутри CalibratedClassifierCV.

### 13. Sparse Matrix — разреженная матрица

**Уровень 1.** Не храним миллионы нулей, если большинство слов отсутствует.

**Уровень 2.** CSR хранит ненулевые data, их column indices и указатели границ строк indptr. Операции sparse работают без превращения всей X в плотный массив.

**Уровень 3.** При float64 плотная SMS train X потребовала бы 3594·59924·8≈1.72 GB, без накладных расходов; это теоретический расчёт. CSR примерно O(nnz+n) памяти. StandardScaler с центрированием sparse разрушает разреженность, поэтому SMS использует MaxAbsScaler, URL22 dense — StandardScaler.

### 14. Model Inference — применение обученной модели

**Уровень 1.** Новый SMS проходит уже выученные преобразования без нового обучения.

**Уровень 2.** ModelStore загружает joblib один раз, predict_proba использует фиксированные vocabulary/IDF/weights. Неизвестные n-граммы игнорируются TF-IDF; char/manual могут дать сигнал.

**Уровень 3.** Одинаковая версия и preprocessing нужны не меньше, чем сами веса. RF parallel summation может давать отличия порядка 1e-16; поэтому reload проверяют с допуском 1e-12. «Новый неизвестный текст» не означает «новая известная категория»: вне распределения уверенность может быть ошибочной.

### 15. Probability Calibration — калибровка вероятностей

**Уровень 1.** Значение .8 должно примерно соответствовать 80% положительных среди похожих оценок.

**Уровень 2.** SVM выдаёт margin, а sigmoid-калибратор учит отображение margin→P на out-of-fold предсказаниях. Это отличается от подбора порога: калибровка меняет шкалу P, порог меняет решение.

**Уровень 3.** Общая форма p=1/(1+exp(Af+B)), A/B обучаются; знак A зависит от ориентации margin. Теоретически p=.8 ⇒ odds4. Изотоническая калибровка гибче, но требует больше данных. В проекте нет reliability diagram/Brier-анализа, поэтому идеальную калибровку не заявляем.

### 16. Decision Threshold — порог решения

**Уровень 1.** Правило «если вероятность выше числа — тревога».

**Уровень 2.** Threshold не обязан быть.5. choose_threshold перебирает уникальные validationP и выбирает F2 при P≥.85; SMS≈.11356, URLt2≈.28815.

**Уровень 3.** Понижение порога при фиксированных score обычно не уменьшает Recall и не уменьшает FPR; Precision не обязана меняться монотонно на конечной выборке. Пример: дополнительные положительные и отрицательные попадают смешанно. Нельзя подбирать порог после просмотра test.

### 17. Репрезентативность и воспроизводимость

**Уровень 1.** Нужны подходящие примеры и возможность повторить эксперимент.

**Уровень 2.** Seed42 фиксирует случайность split/моделей; hashes фиксируют байты данных/артефактов; версии библиотек фиксируют среду. Это разные гарантии.

**Уровень 3.** Детерминированность не доказывает отсутствие bias: можно идеально повторять ошибочный эксперимент. В проекте сохранены source/licenses/positions/parameters; модели вне Git требуют отдельного доверенного переноса. Байтовый hash модели не равен цифровой подписи доверенного издателя.

## Алгоритмы

### A1. Multinomial Naive Bayes — мультиномиальный наивный Байес

**Уровень 1.** Оценивает, какие слова чаще принадлежат классу.

**Уровень 2.** log P(c|x) пропорционален log P(c)+Σx_j log θ_cj. θ_cj — сглаженная доля признака j в классе c. Нужны неотрицательные входы; TF-IDF поддерживается реализацией, хотя исходная теория описывает counts.

**Уровень 3.** θ_cj=(N_cj+α)/(Σ_j N_cj+αd), d — размер словаря. Для counts[3,1],α1, d2 получаем[4/6,2/6]. Сглаживание предотвращает нулевую вероятность. В проекте baselinealpha1, лучшая NB validationalpha.1; это разные варианты.

### A2. Logistic Regression — логистическая регрессия

**Уровень 1.** Суммирует признаки с весами и переводит число в вероятность.

**Уровень 2.** z=w·x+b, p=σ(z)=1/(1+exp(−z)); несмотря на название, здесь классификация. Обучается логистическая функция потерь с регуляризацией.

**Уровень 3.** L=−Σ[y ln p+(1−y)ln(1−p)]+λ||w||²/2. При z=ln4 p=.8. Большее C означает более слабый штраф в данной реализации. class_weight меняет вклад примеров; predict_proba не гарантирует калибровку на другом распределении.

### A3. Support Vector Machine — машина опорных векторов

**Уровень 1.** Ищет разделяющую границу с большим зазором.

**Уровень 2.** Линейная функция f=w·x+b определяет сторону границы. Soft margin допускает ошибки за штраф. Margin не является вероятностью.

**Уровень 3.** Классическая цель .5||w||²+CΣmax(0,1−yᵢfᵢ), y∈{−1,+1}; зазор 2/||w||. Если ||w||=2, зазор 1 в scaled-пространстве. LinearSVC по умолчанию использует squared_hinge, поэтому эту общую формулу нельзя буквально приписывать ему без уточнения.

### A4. LinearSVC — линейная SVM в scikit-learn

**Уровень 1.** Эффективная линейная модель для разреженного текста.

**Уровень 2.** В проекте balanced, dual=False, max_iter10000, C10. Это не SVC с RBF-ядром (радиальной базисной функцией); собственного predict_proba нет. Используется калибратор.

**Уровень 3.** Squared hinge=max(0,1−yf)²: при yf=.5 потеря.25, при yf1.2 потеря 0. dual выбирает форму задачи оптимизации, а не вероятность. В calibration-fold должны обучаться и признаки, не только коэффициенты classifier.

### A5. CalibratedClassifierCV — калибровка с CV

**Уровень 1.** Учит перевод margin в вероятность на невиденных оценках.

**Уровень 2.** OOF — предсказание объекта моделью, не учившейся на нём. ensemble=False обучает один калибратор на OOF и базовый estimator на всём train.

**Уровень 3.** p=1/(1+exp(Af+B)), A/B учатся; знак A зависит от ориентации f. Например p.8 даёт odds4. Sigmoid отличается от isotonic — монотонной непараметрической калибровки, требующей больше данных. В проекте нет отдельного Brier/reliability-исследования.

### A6. Decision Trees — деревья решений

**Уровень 1.** Последовательно проверяют условия о признаках.

**Уровень 2.** Узел сравнивает x_j с t, лист хранит классовые доли. Разбиение выбирается по снижению impurity — неоднородности.

**Уровень 3.** Gini=1−Σp_c²: для[.5,.5] это.5, для[1,0]0. Gain=I_parent−n_L/n·I_L−n_R/n·I_R; n_L/R — размеры потомков. Глубина ограничивает сложность. Путь дерева не доказывает причинное влияние признака на реальную угрозу.

### A7. Random Forest — случайный лес

**Уровень 1.** Много разных деревьев усредняют ответы.

**Уровень 2.** Bootstrap-подвыборки (выборки с возвращением) и случайный выбор признаков уменьшают корреляцию деревьев. В URL150 деревьев, depth12, balanced, seed42.

**Уровень 3.** P_RF=(1/B)ΣP_b, B — число деревьев. Для P[.2,.6,.7] среднее.5. Это средние классовые доли листьев, не обязательно большинство бинарных голосов. Impurity importance смещена в пользу признаков с большим числом разбиений и не является локальной атрибуцией.

### A8. Почему классические модели

**Уровень 1.** Быстро обучаются на небольшом корпусе и легко проверяются.

**Уровень 2.** Sparse TF-IDF подходит линейным алгоритмам,22 табличных URL-признака — деревьям. Не нужны GPU и большой корпус для fine-tuning, то есть дополнительной настройки нейросети.

**Уровень 3.** Это инженерный выбор ТЗ, не доказательство превосходства над нейросетями. Важны данные, вычислительная цена, воспроизводимость и прозрачный протокол. Сравнения с BERT в SMS Guard не было; заявлять победу над ним нельзя.

### A9. Почему не BERT, LSTM или Transformers

**Уровень 1.** Более сложная модель не решает нехватку данных автоматически.

**Уровень 2.** LSTM — рекуррентная сеть с памятью; Transformer использует self-attention, внимание между элементами; BERT — предварительно обученный двунаправленный Transformer. Этих моделей в проекте нет.

**Уровень 3.** Attention(Q, K, V)=softmax(QKᵀ/√d_k)V; Q, K, V — запросы, ключи, значения, d_k — размер ключа. Для двух равных scores softmax даёт[.5,.5]. Стандартная матрица внимания квадратична по длине. Это теория, не реализация SMS Guard; нужен отдельный бюджет и протокол.

## Метрики

### M1. Confusion Matrix — матрица ошибок

**Уровень 1.** Таблица верных и ошибочных решений.

**Уровень 2.** В проекте [[TN, FP],[FN, TP]], строки — истина 0/1, столбцы — прогноз 0/1. SMS[[672,6],[5,88]].

**Уровень 3.** N=672+6+5+88=771. Всегда подписывать оси и positive class. Матрица относится к одному порогу и бинарной модели, а не автоматически к общему Risk Score.

### M2. True Positive — истинно положительный

**Уровень 1.** Положительный пример найден правильно.

**Уровень 2.** TP=88 для SMS: модель назвала spam то, что размечено spam.

**Уровень 3.** TP=Σ1[y=1 и ŷ=1]. Из 93 положительных 88 найдены. Это факт разметки UCI, а не подтверждение юридического мошенничества этих сообщений.

### M3. True Negative — истинно отрицательный

**Уровень 1.** Отрицательный пример оставлен отрицательным.

**Уровень 2.** TN=672 SMS из 678 ham.

**Уровень 3.** TN=Σ1[y=0 и ŷ=0]; ещё 6 ham стали FP. Категория общего риска может отличаться от бинарной метки SVM, поскольку участвуют правила и URL.

### M4. False Positive — ложная тревога

**Уровень 1.** Отрицательный пример ошибочно объявлен положительным.

**Уровень 2.** FP=6 SMS и 921 URL на test. Они снижают Precision и доверие пользователя.

**Уровень 3.** FPR=FP/(FP+TN): SMS6/678≈.00885. FPR не равно 1−Precision, знаменатели разные. Пример example.com/about — отдельный демонстрационный FP, не обязательно одна из 921 test-строк.

### M5. False Negative — пропуск

**Уровень 1.** Положительный пример ошибочно оставлен отрицательным.

**Уровень 2.** FN=5 SMS и 571 URL. Для защиты пропуск часто дороже ложной тревоги.

**Уровень 3.** FNR=FN/(FN+TP)=1−Recall: SMS5/93≈.05376. Уменьшение порога может сократить FN, но увеличить FP, поэтому требуется ограничение Precision.

### M6. Accuracy — доля правильных

**Уровень 1.** Какая часть всех ответов верна.

**Уровень 2.** A=(TP+TN)/N: SMS760/771=.985733.

**Уровень 3.** Всегда ham на чистом UCI дало бы 4517/5135≈.8796, но Recall spam0. Дисбаланс делает Accuracy недостаточной. Нужны метрики positive и абсолютные ошибки.

### M7. Precision — точность положительных

**Уровень 1.** Сколько тревог действительно положительные.

**Уровень 2.** P=TP/(TP+FP): SMS88/94=.936170, URL1655/2576=.642469.

**Уровень 3.** P=TPRπ/(TPRπ+FPR(1−π)), π — доля positive. При TPR.9, FPR.1,π.1 получаем.5. Если положительных прогнозов нет, код использует zero_division=0.

### M8. Recall — полнота

**Уровень 1.** Какую долю реальных положительных нашли.

**Уровень 2.** R=TP/(TP+FN): SMS88/93=.946237, URL1655/2226=.743486.

**Уровень 3.** Recall=TPR. Модель всегда positive даст R1, но P равна доле positive. Поэтому один Recall не показывает цену ложных тревог; у очищенного UCI эта доля около.12.

### M9. F1-score — гармоническое среднее

**Уровень 1.** Одна оценка баланса точности и полноты.

**Уровень 2.** F1=2PR/(P+R)=2TP/(2TP+FP+FN); SMS176/187=.941176.

**Уровень 3.** При P1, R.5 F1=.6667, а арифметическое среднее.75. F1 сильнее штрафует слабую компоненту, но не использует TN и не заменяет оценку стоимости ошибок.

### M10. F2-score — усиленный приоритет полноты

**Уровень 1.** Похож на F1, но сильнее учитывает Recall.

**Уровень 2.** Fβ=(1+β²)PR/(β²P+R); β2 даёт 5TP/(5TP+4FN+FP). SMS440/466=.944206.

**Уровень 3.** При TP8, FN2, FP2 получаем 40/50=.8. β²4 — вес в формуле, не универсальная финансовая цена. F2 не равно 2F1; критерий выбирался на validation при P≥.85.

### M11. ROC Curve — кривая обнаружения и ложных тревог

**Уровень 1.** Меняем порог и смотрим компромисс.

**Уровень 2.** Ось X=FPR, Y=TPR; нужны scores, не только labels.

**Уровень 3.** При пороге выше всех scores точка(0,0), ниже всех —(1,1). SMS текущий порог даёт(.00885,.94624): это одна точка, не площадь. ROC не показывает Precision напрямую.

### M12. ROC-AUC — площадь под ROC

**Уровень 1.** Насколько положительные обычно стоят выше отрицательных.

**Уровень 2.** AUC=∫TPR dFPR; SMS.996035, URL.844709.

**Уровень 3.** AUC=P(score_pos>score_neg)+.5P(tie). Для positive[.8,.6], negative[.7,.1] успешны 3 из 4 пар, AUC.75. Высокая AUC не гарантирует хорошую Precision при любом пороге и prior.

### M13. Precision-Recall Curve — кривая точности и полноты

**Уровень 1.** Показывает ложные тревоги при поиске всё большей доли угроз.

**Уровень 2.** По X Recall, по Y Precision; полезна для редкого positive.

**Уровень 3.** Precision на конечной выборке может колебаться немонотонно. Базовый уровень связан с долей positive, здесь SMS93/771≈.1206. PR между наборами с разными prior сравнивать нужно осторожно.

### M14. PR-AUC — трапецеидальная площадь PR

**Уровень 1.** Суммирует качество по диапазону Recall.

**Уровень 2.** В metrics вызывается auc(recall, precision): SMS.985589, URL.835703.

**Уровень 3.** Для точек(0,1),(.5,.8),(1,.5) площадь.5·.9+.5·.65=.775. Трапеции предполагают линейную интерполяцию. Это теоретический пример, не новый эксперимент проекта.

### M15. Average Precision — средняя точность по приростам Recall

**Уровень 1.** Другой способ суммирования PR-качества.

**Уровень 2.** AP=Σ(R_k−R_(k−1))P_k; SMS.985636, URL.834934.

**Уровень 3.** На тех же учебных точках AP=.5·.8+.5·.5=.65 при ступенчатой интерпретации. AP и трапецеидальная PR-AUC различаются определением; нельзя молча подменить одну другой.

### M16. Latency — задержка

**Уровень 1.** Сколько времени ждём результата.

**Уровень 2.** Single inference, полный API-запрос и batchtime/N измеряют разные вещи. Median — медиана, p95 —95-й процентиль.

**Уровень 3.** Если 100 объектов обработаны за 1 с,10ms/объект — амортизированная цена, не обязательно single latency. Исторически SMS singlemedian≈10.72ms, APIp95≈93.39ms. Железо, длина и прогрев влияют на время; универсальной гарантии нет.

## Что считать на защите

Нарисуйте CM, подпишите оси, выпишите TP/FP/FN/TN, посчитайте P/R/F1/F2, затем объясните выбор порога и независимость test. Теоретическая формула не доказывает, что соответствующий эксперимент был проведён в проекте.

## Дополнительные термины математического ответа

Опорные векторы — объекты у границы или с нарушением margin-условия, влияющие на решение SVM. L1/L2 — нормы: ||w||₁=Σ|w_j|, ||w||₂=√Σw_j²; для[3,4] это7 и5. Регуляризация — штраф сложности; она не гарантирует отсутствия переобучения.

Bootstrap — выборка с возвращением: один объект может появляться несколько раз, другой не попасть. Bagging — усреднение моделей на таких выборках; случайный лес дополнительно случайно выбирает признаки при разбиениях. OOF уже означает невиденность конкретного объекта при получении его оценки, а не использование test.

CSR (Compressed Sparse Row) — построчное сжатое хранение разреженной матрицы. Out of vocabulary, OOV — элемент вне обученного словаря. Distribution shift — смена распределения входов/классов. Reliability diagram — график соответствия предсказанных вероятностей наблюдаемым частотам; Brier score=(1/n)Σ(pᵢ−yᵢ)² — средняя квадратичная ошибка вероятностей. Для одного y1,p.8 вклад.04. В SMS Guard отдельное исследование этими средствами не проведено; это теория будущей проверки.

Учебный пример CV: пять оценок .80,.90,.85,.90,.95 дают среднее .88. Разброс важен вместе со средним; это придуманные для объяснения числа, не результаты folds SMS Guard. Для норм ошибки при x=[3,4] L2=5; для памяти dense n×d×8 — только объём чисел float64, не весь процесс Python. Эти примеры помогают объяснять символы, не заменяя измерения проекта.
